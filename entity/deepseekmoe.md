# DeepSeekMoE：面向极致专家专门化的混合专家语言模型——中文总结

DeepSeekMoE 是 DeepSeek-AI 等机构提出的一种混合专家语言模型架构及同名论文，核心方法是通过细粒度专家切分和共享专家隔离提高专家专门化程度与参数效率。

## 一句话概括

论文通过“细粒度专家切分”和“共享专家隔离”两项设计，让 MoE 模型中的路由专家学习更少重叠、更聚焦的知识，从而以较少的激活参数和计算量取得接近更大稠密模型的效果。

## 研究背景与核心问题

混合专家模型（Mixture-of-Experts，MoE）在每个 token 上只激活少量专家，因此能够增加模型总参数量而不同比例增加计算量。传统 GShard 类 MoE 通常从 N 个完整 FFN 专家中选择 Top-K 个，但论文认为这种设计存在两个问题：

1. 知识混杂：专家数量较少时，一个专家需要处理多种差异很大的知识，难以形成明确分工。
2. 知识冗余：不同 token 需要的通用知识会被多个路由专家重复学习，浪费专家参数。

DeepSeekMoE 的目标不是单纯增加专家数量，而是在总专家参数量和单 token 计算量基本不变的条件下，提高专家专门化程度和参数利用率。

## 方法

### 1. 细粒度专家切分

传统 MoE 有 N 个专家，每个 token 激活 K 个。DeepSeekMoE 将每个专家沿 FFN 中间维度切成 m 个更小的专家，于是专家总数变为 mN；同时每个 token 激活 mK 个小专家。每个小专家只有原专家约 1/m 的规模，所以总专家参数量和激活计算量基本保持不变。

这一设计带来更灵活的专家组合。例如，N=16、K=2 时，传统 Top-2 只有 C(16,2)=120 种组合；若每个专家切成 4 份，则从 64 个小专家中激活 8 个，理论组合数达到 C(64,8)=4,426,165,368。论文据此认为，不同知识可以被更精细地分散到不同专家中。

### 2. 共享专家隔离

模型从全部专家中划出 Ks 个共享专家，并让每个 token 都固定经过这些共享专家；路由器只在剩余专家中进行稀疏选择。共享专家负责承载跨上下文的通用知识，路由专家则更专注于差异化知识。

在完整架构中：

- 共享专家数为 Ks，始终激活；
- 路由专家数为 mN-Ks；
- 每个 token 再激活 mK-Ks 个路由专家；
- 共享与路由专家的激活总数仍为 mK。

### 3. 负载均衡

论文同时使用两类辅助损失：

- 专家级均衡损失：避免路由塌缩，即大量 token 长期只选择少数专家；
- 设备级均衡损失：在专家分布于多个设备时平衡设备计算负载。

作者强调，过强的专家级均衡约束会损害模型效果，因此实际训练中采用较小的专家级系数，并在需要专家并行时采用更大的设备级系数。

## 实验设计与主要结果

### 1. 2B 规模验证实验

- 训练数据：内部多语言语料的 100B token 子集，以中英文为主，也包含网页、数学、代码和出版物等内容。
- DeepSeekMoE：约 2.0B 总参数、0.3B 激活参数；1 个共享专家加 63 个路由专家，每个 token 激活 1 个共享专家和 7 个路由专家。
- 对比模型：Dense、Hash Layer、Switch Transformer、GShard。
- 评测覆盖语言建模、常识与推理、阅读理解、代码生成和闭卷问答。

在总参数与激活参数相同的条件下，DeepSeekMoE 明显优于 GShard：

| 指标 | GShard 2B | DeepSeekMoE 2B |
|---|---:|---:|
| Pile Loss（越低越好） | 1.867 | 1.808 |
| HellaSwag | 50.5 | 54.8 |
| ARC-Challenge | 31.6 | 34.3 |
| TriviaQA | 10.2 | 16.6 |
| NaturalQuestions | 3.2 | 5.7 |

作者还报告：

- DeepSeekMoE 2B 的整体表现与专家参数和专家计算量均为其 1.5 倍的 GShard×1.5 相当；
- 它接近具有 16 倍 FFN 参数、全部参数均被激活的 Dense×16，论文将后者视为该实验设置下 MoE 模型容量的严格上界；
- 在约 13.3B 的扩展实验中，DeepSeekMoE 还能明显超过更大的 GShard×1.5。

### 2. 专家专门化证据

消融与干预实验支持两项核心设计：

- 单独加入共享专家通常优于 GShard；继续提高专家切分粒度，整体效果持续提升；
- 禁用路由概率最高的专家时，DeepSeekMoE 的损失上升比 GShard×1.5 更快，说明其关键专家更难被其他专家替代，路由专家间冗余更低；
- 禁用共享专家并额外激活一个路由专家后，Pile Loss 从 1.808 恶化到 2.414，表明共享专家承担了路由专家难以替代的基础知识；
- DeepSeekMoE 只激活 4 个路由专家时即可达到完整 GShard 的 Pile Loss；从头训练一个只激活一半专家计算量的版本，仍能超过 GShard。

这些结果说明细粒度专家并非只增加了组合数量，而是确实提高了激活参数中的有效信息比例。不过，论文采用的是性能退化和消融等间接指标，并未证明每个专家都形成了人类可解释的语义类别。

### 3. DeepSeekMoE 16B

- 总参数：16.4B；单 token 激活参数：约 2.8B。
- 结构：28 层、隐藏维度 2048；除首层外均使用 MoE；每层含 2 个共享专家和 64 个路由专家，每个 token 激活 2+6 个专家。
- 训练：2T token，最大序列长度 4K。

与在相同内部语料、相同 2T token 上训练的 DeepSeek 7B 稠密模型相比：

| 项目 | DeepSeek 7B Dense | DeepSeekMoE 16B |
|---|---:|---:|
| 总参数 | 6.9B | 16.4B |
| 激活参数 | 6.9B | 2.8B |
| 每 4K token FLOPs | 183.5T | 74.4T |
| 相对计算量 | 100% | 40.5% |
| Pile BPB（越低越好） | 0.75 | 0.74 |
| HellaSwag | 75.4 | 77.1 |
| HumanEval | 26.2 | 26.8 |
| TriviaQA | 59.7 | 64.8 |
| MMLU | 48.2 | 45.0 |

总体上，DeepSeekMoE 16B 只用约 40% 的计算量获得与 DeepSeek 7B 相当的性能，在语言建模和知识密集型任务上较强，但在 MMLU、CEval、CMMLU 等多项选择任务上落后。作者将这一弱点归因于注意力参数量较少：DeepSeekMoE 16B 约有 0.5B 注意力参数，而 DeepSeek 7B 约有 2.5B。

论文还将其与 LLaMA2 7B 比较：DeepSeekMoE 16B 使用 39.6% 的计算量，在多数内部评测中更好或相当，代码、数学和中文任务优势尤其明显。但两者的训练语料组成不同，因此这部分结果同时受架构与数据差异影响，不如和 DeepSeek 7B 的同数据比较严格。

作者称该模型无需量化即可部署在一张 40GB 显存 GPU 上；配合算子优化，推理速度可接近 7B 稠密模型的 2.5 倍。这里的速度是作者报告的优化结果，FLOPs 优势不必然等同于所有硬件和推理框架上的实际加速。

### 4. 监督微调与聊天模型

作者使用内部整理的 1.4M 条中英文指令数据，对 DeepSeekMoE 16B 进行 8 个 epoch 的监督微调。DeepSeekMoE Chat 16B 在约 40% 稠密模型计算量下，与使用相同 SFT 数据的 DeepSeek Chat 7B 和 LLaMA2 SFT 7B 在多数任务上相当：

- HumanEval 和 MBPP 等代码任务表现突出；
- 中英文能力较均衡；
- 多项选择任务仍弱于 DeepSeek Chat 7B；
- 结果证明 MoE 模型也能从指令微调中明显受益。

### 5. 145B 初步扩展实验

- DeepSeekMoE 145B：144.6B 总参数、22.2B 激活参数；每层 4 个共享专家加 128 个路由专家，每个 token 激活 4+12 个专家。
- 训练仅进行到 245B token，因此属于初步、未完成的规模化实验。
- 它在相近总参数和计算量下明显优于 GShard 137B。
- 与 DeepSeek 67B 稠密模型相比，作者报告其以 28.5% 的 FLOPs 获得总体相当的效果。
- 一个只激活 12.2B 参数的 DeepSeekMoE 142B 版本，以 18.2% 的 FLOPs 仍取得接近 DeepSeek 67B 的总体表现，并超过 GShard 137B。

## 论文贡献

1. 提出一种面向专家专门化的 MoE 架构，将细粒度专家切分和共享专家隔离结合起来。
2. 在固定总参数和计算量的对照中，显示该架构比传统 GShard 更高效。
3. 通过专家禁用、共享专家移除和减少激活专家等实验，为“更低冗余、更准确路由”提供经验性证据。
4. 将方法扩展到 16B，并初步扩展到约 145B，展示规模可扩展性。
5. 证明该 MoE 模型能够通过监督微调形成聊天模型，并公开 DeepSeekMoE 16B 权重。

## 局限与阅读时应注意的地方

1. “接近 MoE 理论上界”只在论文构造的 Dense×16 对照、约 2B 参数和 100B token 设置中成立，不代表所有规模和训练条件下的普遍理论证明。
2. 145B 实验只训练了 245B token，论文也明确称其为 ongoing；28.5% 和 18.2% 计算量结论应视为初步结果。
3. 预训练语料和 1.4M SFT 数据均为内部数据，外部研究者难以完全复现，也难以严格拆分架构、数据质量与数据配比各自带来的收益。
4. 与 LLaMA2 等外部模型的比较并未控制训练数据；同语料的 DeepSeek 7B 对照更能说明架构效率。
5. 稀疏 MoE 的实际吞吐量还受到路由、专家通信、负载均衡、批量大小和专用算子影响，FLOPs 降低不能直接等价为相同幅度的实际速度或成本下降。
6. 模型在多项选择任务上存在明显短板，说明大量专家 FFN 参数不能完全补偿注意力容量不足。
7. 专家禁用敏感性说明参数冗余降低，但不等于专家已经形成稳定、可解释且完全不重叠的知识模块。

## 总结性评价

DeepSeekMoE 的关键价值在于重新设计 MoE 的“专家粒度”和“通用知识放置位置”：共享专家吸收公共知识，更多的小型路由专家负责更窄的知识组合。论文的同规模对照、消融实验和扩展实验形成了较完整的证据链，说明这种结构比传统 Top-1/Top-2 大专家路由具有更好的参数效率。最可信的结论是其相对 GShard 的架构优势；关于与外部稠密模型的绝对优劣、超大规模训练收益和真实部署加速，则需要结合数据差异、未完成训练以及硬件实现继续审慎验证。
