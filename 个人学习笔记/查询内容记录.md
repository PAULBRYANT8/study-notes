# 查询内容记录：张量显存、注意力与数据并行

更新：2026-10-08。

这份笔记整理四组相关问题：张量占多少显存；CP 与 FlashAttention 怎样配合；Transformer 的基础概念；batch、BSD 与 DP 切分。公式默认使用行向量约定，具体模型的张量布局仍需结合代码确认。

## 1. 怎样估算一个张量的显存

设隐藏状态为：

$$
X\in\mathbb{R}^{B\times S\times D}
$$

其中，$B$ 是批大小，$S$ 是序列长度，$D$ 是每个 token 的隐藏维度。三个维度的详细解释见第 4 点。

对于稠密张量，逻辑元素的数据量为：

$$
M_X=B\times S\times D\times \text{每元素字节数}
$$

例如，$B=4$、$S=1024$、$D=4096$，使用 BF16（每元素 2 字节）：

$$
M_X=4\times1024\times4096\times2
=33{,}554{,}432\ \text{bytes}
=32\ \text{MiB}
$$

这只是**一个张量的数据量**。训练峰值显存还包括参数、梯度、优化器状态、其他激活、通信缓冲、算子工作区和分配器保留的内存。

另需注意：多个 view 可以共享同一份底层存储，不能把每个 view 的逻辑数据量都当作新增分配；非连续张量的底层存储范围也可能大于其逻辑元素数据量。

阅读：[[deep-learning-training-numerics|训练数值与显存账本]]、[张量视图与存储共享](https://docs.pytorch.org/docs/2.14/tensor_view.html)。

## 2. 为什么需要 CP，它与 FlashAttention 有什么关系

**采用 CP 的直接动机，是在目标序列长度下，通过多卡分担激活和计算，满足显存容量与吞吐需求。**

CP（Context Parallelism，上下文并行）把同一条序列的不同位置分给不同设备。窗口注意力、压缩注意力决定切分后需要补齐哪些跨卡数据；位置与因果语义决定这些数据应怎样被正确使用。

| 技术或模型设计 | 主要解决的问题 |
| --- | --- |
| CP | 将同一序列的 token 及相关计算分配到多卡，降低每卡承担的激活规模 |
| FlashAttention | 用分块、在线 Softmax 和重计算减少注意力内部的显存读写，避免保存完整的 $S\times S$ 分数/概率矩阵 |
| 窗口注意力 | 限定 query 读取的局部 token 范围 |
| 压缩注意力 | 通过压缩表示提供更紧凑的上下文；具体读取规则由模型定义 |

FlashAttention 保持标准注意力的数学语义，但浮点运算顺序不同可能产生数值误差；它仍执行标准稠密注意力所需的二次方量级计算。Q/K/V、输出、残差和 FFN 等激活仍占用显存，因此使用 FlashAttention 后，长序列训练仍可能需要 CP。

在使用 FlashAttention 内核的 CP 实现中：

```text
CP 分配各卡负责的 query/token
    → 通过通信提供它们需要的远端 KV
    → 每张卡执行相应的注意力计算
    → 得到本地负责的输出
```

如果 KV 分多轮到达，需要按全局 Softmax 的归一化关系合并各轮贡献，不能把各块独立归一化的输出直接相加。对于窗口或压缩注意力，也应采用与其语义匹配的算子和通信策略。

阅读：[[context-parallel|CP 原理]]、[[ring-attention|Ring Attention 与 Softmax 合并]]、[FlashAttention 原论文](https://arxiv.org/html/2205.14135v2#S3.SS1)、[[DeepSeek-2026 CP 切分设计方案|项目中的 CP 设计]]。

## 3. 机器学习与 Transformer 的基础概念

### 3.1 模型通过训练学习什么

机器学习通常先定义一个带可调参数的模型，再根据数据和目标函数调整参数，使模型的输出满足任务要求。这里仍然需要人工设计模型结构、损失函数、数据处理和训练方法。

“给定输入和正确输出，让模型模仿”适合解释监督学习。语言模型预训练还可以从文本本身构造监督信号，例如根据前面的 token 预测下一个 token，无需人为逐条标注。

模型参数常被统称为“权重”，但具体可训练量还包括偏置、embedding 表、归一化缩放参数等。以线性变换为例：

$$
y=xW+b
$$

其中 $W$ 是权重矩阵，$b$ 是偏置。模型中还包含激活、归一化、残差相加等运算，参数与数据的作用方式不只有矩阵乘法。

**训练时更新的是模型参数；常规推理时参数固定，随输入变化的是激活和隐藏状态。**

阅读：[[deep-learning-training-numerics|反向传播与参数更新]]。

### 3.2 向量点积表达什么

两个向量的点积为：

$$
a\cdot b=\sum_i a_i b_i=\|a\|\,\|b\|\cos\theta
$$

对于非零向量：

- 夹角小于 $90^\circ$，点积为正。
- 两向量垂直，点积为零。
- 夹角大于 $90^\circ$，点积为负。

点积同时受到**方向和长度**影响。将两向量归一化到单位长度后，点积才等于余弦相似度。

Attention 用学习得到的 Q/K 点积产生匹配分数，再结合缩放、位置处理和 mask 计算权重；不能只凭原始 embedding 的几何方向解释全部注意力行为。

### 3.3 token、embedding 与上下文化表示

token 是 tokenizer 划分出的单位，可以是词、子词、字符或其他片段，不一定对应一个完整词。

embedding 层将 token ID 映射为向量：

```text
token ID → 查 embedding 表 → 初始 token 向量
```

经过 Transformer 各层后，这些向量会融合允许访问的上下文。例如，同一个词在不同句子中，其初始查表向量可以相同，经过上下文计算后的隐藏状态则可以不同。

这里的“逐步调整向量”指的是**前向计算不断生成新的隐藏状态**；只有训练中的参数更新才会修改 embedding 表等模型参数。

上下文长度描述模型一次处理或利用的 token 范围。对因果语言模型，当前位置只能访问规则允许的历史和自身；窗口、稀疏或压缩设计还会进一步规定具体的访问方式。

阅读：[[deepseek-v4-architecture-and-execution|模型组件与执行流程]]、[Embedding 的输入输出](https://docs.pytorch.org/docs/2.14/generated/torch.nn.Embedding.html)。

### 3.4 Q、K、V 从哪里来，维度由什么决定

以自注意力的单个注意力头为例，省略投影偏置和位置处理。设输入隐藏状态：

$$
X\in\mathbb{R}^{B\times S\times D_{\text{model}}}
$$

采用行向量约定：

$$
Q=XW_Q,\qquad K=XW_K,\qquad V=XW_V
$$

相应形状为：

| 对象 | 形状 |
| --- | --- |
| $W_Q$、$W_K$ | $[D_{\text{model}},d_k]$ |
| $W_V$ | $[D_{\text{model}},d_v]$ |
| $Q$、$K$ | $[B,S,d_k]$ |
| $V$ | $[B,S,d_v]$ |

Q 与 K 的最后一维需要匹配，才能计算点积；$d_v$ 可以与 $d_k$ 不同。Q/K/V 来自当前层的输入隐藏状态，通常并不是每层都直接从最初的 embedding 查表结果计算。

在这个公式约定下，**$W_Q$ 的列数决定 Q 的输出维度**。若采用列向量公式 $q=W_Qx$，矩阵方向相反。PyTorch 的 Linear 参数通常按 `[out_features,in_features]` 存储，计算时使用其转置，因此需要区分数学公式和实际参数存储布局。

Q/K 的作用是产生注意力权重，V 提供按这些权重汇聚的内容：

$$
P=\operatorname{softmax}\left(\frac{QK^\top}{\sqrt{d_k}}+M\right),
\qquad O=PV
$$

其中 $M$ 是加性 mask，Softmax 沿 key 维归一化。多头输出通常拼接后再经过输出投影，回到模型隐藏维度，以便进入后续残差计算。

因此，V 不必与 embedding 处在同一个表示空间；可以把注意力分支的投影输出理解为对残差流的更新，但不能直接把原始 V 等同于“embedding 应移动的距离”。

### 3.5 Q/K/V 的参数量有没有固定比例

没有通用的“Value 参数量 = Query 参数量 + Key 参数量”规则。

以常规多头注意力为例，若 Q/K/V 三路投影的输入和总输出宽度都为 $D_{\text{model}}$，忽略偏置，则：

$$
\#W_Q=\#W_K=\#W_V=D_{\text{model}}^2
$$

GQA、MQA、低秩投影以及其他注意力变体会改变投影形状和参数量。分析时应根据具体的输入维度、输出维度与共享方式计算。

Q/K/V 与多头投影的数学定义见 [Transformer 原论文](https://arxiv.org/html/1706.03762v7#S3.SS2)；参数存储方向见 [PyTorch Linear](https://docs.pytorch.org/docs/2.14/generated/torch.nn.Linear.html)。

### 3.6 自注意力和交叉注意力如何区分

| 类型 | Q 的来源 | K/V 的来源 | 例子 |
| --- | --- | --- | --- |
| 自注意力 | 当前序列的隐藏状态 | 同一序列的隐藏状态 | 一段文本内部交换上下文信息 |
| 交叉注意力 | 当前需要更新的序列 | 另一组表示 | 解码器读取编码器输出 |

两者的核心计算形式相同，区别主要在于 Q 与 K/V 的来源。交叉注意力中的 query 长度和 key/value 长度可以不同，“另一组表示”也不一定来自另一个数据集，例如可以是同一个任务样本中的图像特征或编码器输出。

### 3.7 Attention 与 MLP 分别做什么

- **Attention**：根据 Q/K 匹配关系，跨 token 汇聚信息，更新当前位置的表示。
- **MLP/FFN**：通常对每个 token 的特征向量独立执行线性变换、非线性激活或门控；这一子层本身通常不直接混合不同 token。

模型知识分布在多个模块的参数与它们的组合计算中。“MLP 存事实、Attention 取事实”只能作为有限的直觉，不能当作严格分工；MLP 也不负责提供实时外部信息。FFN 的输入已经可能包含上一注意力子层引入的上下文。

阅读：[[glu-variants-improve-transformer|FFN 与门控激活]]、[[deepseek-v4-architecture-and-execution|Transformer 模型执行流程]]。

## 4. batch、BSD 与 DP 切分

### 4.1 batch 指的是什么

**batch 是一次组织起来处理的一组样本，batch size 是这组样本的数量。**

对于语言模型，一个样本通常是一条整理后的 token 序列。它可以来自一句话、文档片段，或多段短文档的打包结果，因此 batch size 不一定等于原始文档数。

例如：

```text
一个 batch：
    样本 0：[token, token, token, ...]
    样本 1：[token, token, token, ...]
    样本 2：[token, token, token, ...]
    样本 3：[token, token, token, ...]

batch size = 4
```

DP（Data Parallelism，数据并行）把不同样本分配给不同的模型副本。下文先假设每个 DP 副本只使用一张卡；组合 TP、CP、PP 时，一个副本也可以由多张卡共同执行。

### 4.2 B、S、D 分别表示什么

| 字母 | 含义 | 解释 |
| --- | --- | --- |
| B | Batch Size，批大小 | 当前张量包含多少条序列 |
| S | Sequence Length，序列长度 | 每条序列有多少个 token 位置 |
| D | Hidden Dimension，隐藏维度 | 每个 token 用多少个数表示 |

例如：

```text
hidden.shape = [4, 1024, 4096]

B = 4：4 条序列
S = 1024：每条序列有 1024 个位置
D = 4096：每个位置用一个 4096 维向量表示
```

对隐藏状态 `X`：

| 访问方式 | 取出的内容 | 形状 |
| --- | --- | --- |
| `X[b]` | 第 b 条序列的全部表示 | `[S,D]` |
| `X[b,s]` | 第 b 条序列中第 s 个 token 的表示 | `[D]` |
| `X[b,s,d]` | 这个 token 向量的第 d 个分量 | 标量 |

因此，$B\times S$ 是 token 位置数，$B\times S\times D$ 是隐藏状态的元素数。D 表示特征向量宽度，不是 token 数或词表大小。

### 4.3 从 token ID 到 BSD 张量

假设分词和补齐后得到以下示意输入，并约定 0 是 padding：

```text
input_ids = [
    [11, 25, 36, 47],
    [52, 63, 74,  0],
]

input_ids.shape = [2,4]
```

此时 $B=2$、$S=4$。若 embedding 维度为 4096：

```text
input_ids：[2,4]          整数 token ID
                ↓ embedding
hidden：   [2,4,4096]     每个 ID 对应一个浮点向量
```

在普通稠密张量中，同一批序列共享张量长度 S，较短的序列可以补齐。上例有 8 个位置，但只有 7 个有效 token；有效注意力和损失计算需要按 mask 处理 padding。

语言模型训练中的常见形状：

| 数据 | 常见形状 | 含义 |
| --- | --- | --- |
| input_ids | `[B,S]` | 输入 token ID |
| labels | `[B,S]` | 各位置的目标 ID 或忽略标记；具体移位由数据和损失接口约定 |
| loss_mask | `[B,S]` | 哪些位置参与损失或其权重 |
| hidden | `[B,S,D_model]` | 各 token 的隐藏表示 |
| logits | `[B,S,VocabSize]` | 各位置对词表的预测分数 |

阅读：[PyTorch Embedding](https://docs.pytorch.org/docs/2.14/generated/torch.nn.Embedding.html)。

### 4.4 DP 怎样沿 B 维切分

假设一次更新处理 8 条序列，$S=1024$、$D=4096$，且没有梯度累积。全局数据的逻辑形状为：

$$
[8,1024,4096]
$$

采用两路 DP：

```text
全局 batch：样本 0、1、2、3、4、5、6、7
                      ↓
rank 0：样本 0、1、2、3     rank 1：样本 4、5、6、7
形状：[4,1024,4096]         形状：[4,1024,4096]
```

DP 改变每个副本承担的样本数量，序列长度 S 和隐藏维度 D 保持不变。input_ids、labels、loss mask 等必须跟随相同的样本分配。

普通 DDP 的一轮计算可以概括为：

```text
各卡持有相同模型参数
    → 各自处理不同样本，执行 forward/backward
    → 同步参数梯度
    → 使用一致的梯度更新各自的参数
```

在各卡样本数相同、损失权重一致的简单情况下，两个副本的梯度可按平均合并：

$$
g=\frac{g_0+g_1}{2}
$$

若各卡有效 token 数不同，而目标是全局有效 token 的平均损失，需要据此安排损失缩放，不能直接把各卡的局部均值等权平均。

**工程实现中的“切 batch”是一种数据分配语义。** 通常由各进程的数据加载器或 sampler 获取不同样本，不必先在一张卡上创建完整全局 batch。PyTorch DDP 本身负责梯度同步，不会自动把传入数据切给其他进程。

阅读：[[dp-fsdp-zero-ep-parallelism|DP、FSDP、ZeRO 与 EP]]、[PyTorch DDP](https://docs.pytorch.org/docs/2.14/generated/torch.nn.parallel.DistributedDataParallel.html)。

### 4.5 microbatch、local batch 与 global batch

讨论 batch size 时，需要同时说明“在哪些设备上”和“跨多少次前反向”。

| 概念 | 本笔记采用的口径 |
| --- | --- |
| 每个 DP 副本的 microbatch size | 一个副本一次 forward/backward 处理的序列数；单卡副本时就是每卡的数量 |
| 每个 DP 副本每次更新处理的样本数 | 该副本在一次参数更新前累计处理的序列数 |
| global batch size | 所有 DP 副本在一次参数更新前合计处理的序列数 |
| 梯度累积次数 | 更新参数前累计多少轮 microbatch 的梯度 |

不同框架对 `local_batch_size` 的命名不完全一致：有的指单次前反向数量，有的指每卡一次更新的累计数量。应沿 DataLoader、microbatch 划分和训练循环确认实际口径。

设每个 DP 副本的 microbatch size 为 $b$，DP 副本数为 $P_{\text{DP}}$，梯度累积次数为 $A$。在每轮等量、没有不完整 batch 的情况下：

$$
B_{\text{global}}=b\times P_{\text{DP}}\times A
$$

例如：

```text
每卡 microbatch size b = 2
DP 副本数 P_DP = 4
梯度累积次数 A = 4
```

| 累积轮次 | 每卡本轮处理 | 所有 DP 副本本轮合计 | 本次更新已累计 |
| --- | --- | --- | --- |
| 第 1 轮 | 2 条 | 8 条 | 8 条 |
| 第 2 轮 | 2 条 | 8 条 | 16 条 |
| 第 3 轮 | 2 条 | 8 条 | 24 条 |
| 第 4 轮 | 2 条 | 8 条 | 32 条 |

完成这 4 轮后再更新参数，因此：

$$
B_{\text{global}}=2\times4\times4=32
$$

而每次模型 forward 真正收到的隐藏状态仍为：

$$
[2,S,D]
$$

这里的 B 是当前 microbatch 的 2。梯度累积通过多轮计算形成更大的有效 batch，不要求把全局 32 条序列的激活同时保存在单卡。累积期间通常先反向释放当前计算图、保留参数梯度，损失还需按所需目标正确缩放。

若每条序列都有 1024 个有效预测位置，这次更新对应 $32\times1024=32768$ 个有效位置；存在 padding、标签忽略或其他 loss mask 时，应统计实际有效位置。

阅读：[PyTorch 梯度累积](https://docs.pytorch.org/docs/2.14/notes/amp_examples.html#gradient-accumulation)、[[2026-09-18-TorchTitan-NPU-会话学习总结|microbatch 与各类 step 的区别]]。

### 4.6 DP 切 B，CP 切 S

对同一个逻辑隐藏状态 `[8,1024,4096]`，分别使用两路 DP 或两路 CP：

| 方式 | 每张卡主要处理什么 | 本地形状示意 |
| --- | --- | --- |
| DP=2 | 8 条序列中的 4 条完整序列 | `[4,1024,4096]` |
| CP=2 | 8 条序列各自的一半位置 | `[8,512,4096]` |

简化为 4 条序列，可以这样理解：

```text
DP：
    卡 0 处理序列 A、B
    卡 1 处理序列 C、D

CP：
    卡 0 处理 A、B、C、D 各自的前半段
    卡 1 处理 A、B、C、D 各自的后半段
```

这里用连续的前后两段作示意，实际 CP 也可以采用交错或其他位置分配方式。CP 切开了同一条序列，因此还需要处理跨片注意力依赖。DP 让不同副本处理不同样本，普通 DDP 主要同步模型参数的梯度。

当单条序列已经放不下、每卡 B 已降到 1 时，增加 DP 副本可以处理更多其他样本，却不能继续分担这一条序列的长度。此时需要评估 CP、重计算、其他并行或内存优化方式。

**全局 batch 公式乘的是 DP 副本数，不是总卡数。** 例如 16 张卡组成 DP=4、TP=2、CP=2，每个 DP 副本用 4 张卡合作计算；若 $b=2$、$A=4$，global batch 仍是 $2\times4\times4=32$，不能把 DP 副本数替换成 16。

阅读：[[tp-vs-cp-sharding|CP 与 TP 的切分区别]]、[[cp-sequence-sharding|CP 序列切分]]。

### 4.7 BSD、BSND 与模型特有维度

字母只是维度记号，必须结合所在张量解释。

| 常见形状 | 维度含义 |
| --- | --- |
| `[B,S,D_model]` | 批大小、序列长度、模型隐藏维度 |

常规多头注意力可能采用：

$$
D_{\text{model}}=4096,\qquad N=32,\qquad D_{\text{head}}=128
$$

于是 $N\times D_{\text{head}}=4096$。这是一种常见配置关系，不是所有注意力变体都必须满足的规则。

在 `[B,S,D]` 中，D 通常表示模型隐藏维度；在 `[B,S,N,D]` 中，D 通常表示每头维度。`[B,S,H]` 的 H 也可能只是 hidden size 的另一种记法，而其他代码中 H 可能代表头数。
